For developers

Exports & events

Send texts and notifications from your scripts, read contacts, hook into calls and messages, and store data for your own apps.

One rule: source or number

Wherever a server export takes a target, you can pass either a player source (1) or a phone number ('555-0134').

  • A number works even when its owner is offline, wherever that makes sense: texts and contacts are saved, and appear the next time the phone opens.
  • With SIM cards on, a source means "the phone this player is holding right now".
  • Notifications are the exception: they aren't stored, so an offline target gets nothing and the export returns false.
local phone = exports['royal-phone']

phone:SendMessage(source, 'Maze Bank', 'Your card was used at 24/7.')      -- a player
phone:SendMessage('555-0134', 'Maze Bank', 'Your card was used at 24/7.')  -- a number, online or not

Server exports

Identity

ExportReturns
GetNumber(source)The number of the phone the player is holding, or nil (no phone or no SIM).
GetSourceFromNumber(number)The source of the online player with that number, or nil.
GetIdentity(target){ number, owner, source, name, serial } or nil. owner is the key the phone stores data under: the SIM serial with SIM cards on, the character identifier otherwise.
local number = exports['royal-phone']:GetNumber(source)
if not number then
    return lib.notify(source, { type = 'error', description = 'You need a phone for this.' })
end

Notifications

ExportReturns
Notify(target, data) / SendNotification(target, data)true if delivered, false if the target is offline.
exports['royal-phone']:Notify(source, {
    app = 'bank',                         -- whose icon and colour to use
    title = 'Paycheck',
    content = 'You received $1,850 from LSPD.',
    duration = 5000,                      -- ms; 0 keeps it up until dismissed
    sound = true,                         -- false adds it silently
})
FieldDescription
titleBold first line. Required.
contentThe text below it (up to two lines shown).
appApp id for the icon, and the app opened when it's tapped: messages, dialer, bank, documents, lifeinvader, garage, … or a custom app's id.
avatarImage URL shown instead of the app icon.
durationMilliseconds on screen. Defaults to Config.NotifyDuration. 0 stays until dismissed.
soundfalse for a silent notification.
routeWhere tapping it should land (see below).

Messages

ExportReturns
SendMessage(target, from, content, extra?)The message id, or false.
GetMessages(target, with?, limit?)Messages newest first. Only the thread with with if given. limit defaults to 50, at most 200.

from is what the conversation is filed under: a phone number, or a name like 'Maze Bank' for a service the player can't reply to. Messages are capped at 500 characters.

-- A dispatch text with a location the player can tap to set a waypoint
exports['royal-phone']:SendMessage(source, 'Dispatch', '10-31 in progress at Legion Square', {
    kind = 'location',
    location = { label = 'Legion Square', x = 195.2, y = -933.9 },
})

-- The last 20 messages between two numbers
local thread = exports['royal-phone']:GetMessages('555-0134', '555-0192', 20)
extra fieldDescription
kind'text' (default), 'image', 'voice' or 'location'.
mediaImage or audio URL (or data URL) for image and voice messages.
secondsLength of a voice message.
location{ label, x, y } for a location message.
nameName shown on the notification, if different from from.

Contacts

ExportReturns
GetContacts(target){ id, name, number, avatar }[], sorted by name.
AddContact(target, { name, number, avatar? })The contact id. If a contact with that number exists, it's renamed instead of duplicated.
RemoveContact(target, number)true if one was removed.
-- Give every new cop the dispatch number
AddEventHandler('myjobs:hired', function(source, job)
    if job == 'police' then
        exports['royal-phone']:AddContact(source, { name = 'LSPD Dispatch', number = '911' })
    end
end)

Calls

ExportReturns
GetCall(source){ id, number, with, outgoing, answered, since } if the player is on (or dialing) a call, else nil. with is the other player's source.
EndCall(source)Hangs up their call. true if there was one.
-- Signal jammer: drop calls when someone enters the zone
if exports['royal-phone']:GetCall(source) then
    exports['royal-phone']:EndCall(source)
end

Bank

ExportReturns
AddTransaction(source, label, amount)Adds a line to the Bank app's activity. Negative amounts are money out. This only logs: move the actual money with your framework as usual.
AddInvoice(source, label, amount, sender?, options?)Bills a player. Returns the invoice id, or false (player not found, amount not positive, or Config.BankInvoices is off).
exports['royal-phone']:AddTransaction(source, 'Paycheck · LSPD', 1850)
exports['royal-phone']:AddTransaction(source, 'Fuel · Ron', -93)

Invoices

AddInvoice sends the player a notification with Pay and Decline, and adds the invoice to the Bank app's Invoices tab. Paying takes the money from their bank account and logs it in Activity. You don't move any money yourself.

-- A speeding ticket that can't be declined
local id = exports['royal-phone']:AddInvoice(source, 'Speeding · 92 in a 50', 750, 'LSPD', {
    canDecline = false,
})

-- A mechanic's bill the player may decline
exports['royal-phone']:AddInvoice(target, 'Engine repair', 1200, "Benny's Motorworks")
ArgumentDescription
sourceThe player to bill (online). The invoice is stored on their character, not their SIM.
labelWhat it's for, up to 64 characters.
amountWhat they owe. Must be positive.
senderWho is charging, shown under the label.
options.canDeclinefalse removes the Decline button: it must be paid. Default true.

A declined invoice stays unpaid on the player's record and can still be paid later.

Contracts

ExportReturns
CreateContract(fromSource, toSource, opts)The document id, or false, reason.

Creates a signable document owned by fromSource, shares it with toSource, and sends them a "Contract to sign" notification. Both players must have a phone.

local id, err = exports['royal-phone']:CreateContract(bossSource, hireSource, {
    title = 'Employment Contract',
    company = 'Downtown Cab Co.',     -- shown in the notification
    banner = 'legal',                 -- slate, ocean, dusk, ember, forest, sand, ice, rose, mono, legal
    body = '<h2>Terms</h2><p>The employee agrees to...</p>',
})

reason is one of 'phone_identity' (a player has no phone), 'same_person' or 'insert_failed'.

Custom apps

ExportReturns
SendAppMessage(source, appId, type, data)Pushes a message into a custom app's page on one player's phone. The page gets it with RoyalPhone.on(type, fn).
GetAppData(target, appId, key)The stored value, or nil.
SetAppData(target, appId, key, value)true when saved. Any JSON-able value up to 64 KB. nil deletes the key.

App data is stored per phone (per SIM card when SIMs are on). See Make your own app.

    end
end)

Server events

The phone fires these on the server so other resources can react.

Use AddEventHandler, never RegisterNetEvent

These events are fired on the server only. If you register them as net events, any client could fire them with fake data.

EventArguments
royal-phone:messageSentmessage { id, sender, receiver, content, kind, media, seconds, location, name, createdAt } and meta { source, receiverSource?, group? }. meta.source is nil when a script sent it.
royal-phone:callStarted{ id, callerSource, receiverSource, callerNumber, receiverNumber }: the phone is ringing.
royal-phone:callAnsweredSame shape.
royal-phone:callEndedSame, plus answered, duration (seconds), reason ('hangup', 'declined', 'unavailable', 'dropped') and endedBy.
royal-phone:contactAddedphone { owner, number, source } and contact { id, name, number }.
royal-phone:bankTransfer{ source, targetSource, fromNumber, toNumber, amount }
-- Log every call longer than a minute to Discord
AddEventHandler('royal-phone:callEnded', function(call)
    if call.answered and call.duration >= 60 then
        logToDiscord(('%s called %s for %ds'):format(call.callerNumber, call.receiverNumber, call.duration))
    end
end)

-- A text-based bot: reply when someone texts 911
AddEventHandler('royal-phone:messageSent', function(message, meta)
    if message.receiver == '911' and meta.source then
        exports['royal-phone']:SendMessage(meta.source, '911', 'Dispatch received your message.')
    end
end)

Client events

Fired on the player's own client. Listen with AddEventHandler.

EventArguments
royal-phone:phoneOpened / royal-phone:phoneClosedNone.
royal-phone:appOpened / royal-phone:appClosedThe app id (built-in or custom).
royal-phone:messageReceivedThe message.
royal-phone:notificationThe notification table.
royal-phone:incomingCall / royal-phone:outgoingCall{ number, name }
royal-phone:callAnswered{ number, name }
royal-phone:callEnded{ number, name, reason }
royal-phone:client:voiceMessageThe length in seconds, when the player records a voice note.
-- Turn the radio down during calls
AddEventHandler('royal-phone:callAnswered', function() SetRadioVolume(0.2) end)
AddEventHandler('royal-phone:callEnded', function() SetRadioVolume(1.0) end)

Events you can trigger

From the server with TriggerClientEvent (or locally on the client):

EventPayload
royal-phone:client:notifyA notification table. Same as the Notify export.
royal-phone:client:refresh'data', 'documents' or 'lifeinvader': re-reads that part of an open phone after you changed it in the database.
Prefer exports

The exports validate input, store things properly and fire the events above. Writing to the phone's tables directly works, but skips all of that.
