Getting started

Configuration

Everything a server owner normally changes is in config.lua. The one exception is the upload host key, which lives in server/upload.lua so it never reaches players.

config.lua is downloaded by every player

It's a shared script, so anything in it can be read by clients. Never put API keys, webhooks or passwords there.

Framework & items

OptionDefaultWhat it does
Config.Framework'QBX'Which bridge to load: 'QBX', 'ESX', 'OX', 'ND' or 'STANDALONE'. See Frameworks.
Config.RequireItemtrueOnly open the phone if the player carries the phone item.
Config.ItemName'phone'Name of that item.
Config.Inventory'ox_inventory'Where to look for the item: 'ox_inventory', 'qb-inventory' or 'none'.
Config.RequireSimtrueThe number and its data belong to a SIM card rather than the character. ox_inventory only. See SIM cards.
Config.SimItem'simcard'Name of the SIM card item.
Config.SimPrefix'SIM'Prefix of generated SIM serials, e.g. SIM-4821-0093.

Controls

OptionDefaultWhat it does
Config.OpenKey'M'Default key to open and close the phone. Players can rebind it in Settings › Key Bindings › FiveM ("Royal Phone - Toggle").
Config.Command'phone'Chat command that does the same (/phone).
Config.AnswerKey'Y'Answer a ringing call without opening the phone.
Config.DeclineKey'N'Decline a ringing call, or hang up a live one.
Config.AllowMovementtrueWalk, run, jump and drive with the phone open. The camera is locked while it's open. false freezes the player until the phone closes.

The answer and decline keys are rebindable by players too, as "Royal Phone - Answer call" and "Royal Phone - Decline / hang up".

Behaviour

OptionDefaultWhat it does
Config.BlockWhenDeadtrueThe phone won't open while the player is dead, and closes if they die.
Config.BlockWhenCuffedtrueThe phone won't open while cuffed.
Config.UseAnimationtrueThe character holds a phone prop: in front of them while it's open, at the ear during calls.
Config.Voice'pma-voice'Voice resource for call audio. 'none' keeps calls silent.
Config.NearbyRange12.0Metres within which another player counts as "nearby" for sharing contacts and documents.

Notifications

OptionDefaultWhat it does
Config.NotifyDuration5000Milliseconds a notification stays on screen when the sender doesn't specify. Notifications then disappear on their own and stay in the notification centre.
Config.PeekDuration1500Milliseconds the pocketed phone peeks up to show a new notification before it slides back down.
Config.NotifyWhenClosedtrueShow notifications while the phone is pocketed. false means players only see them when they open the phone.

Phone numbers

OptionDefaultWhat it does
Config.NumberFormat'###-####'Pattern for new numbers. Every # becomes a random digit, and duplicates are never handed out.
Config.NumberPrefix''Text put in front of every generated number, e.g. '555-'.

Without SIM cards, a framework that already stores a phone number (QBX charinfo.phone, for example) keeps using it, and only characters without one get a generated number.

Documents

OptionDefaultWhat it does
Config.DocumentMaxLength60000Largest document body (characters of HTML) the Documents app stores. Anything longer is cut off by the server.

Photos & voice notes

OptionDefaultWhat it does
Config.MediaStorage'database'Where photos and voice clips go: 'database' or 'remote'. See below.
Config.PhotoEncoding'webp'Camera image format: 'webp', 'jpg' or 'png'.
Config.PhotoMaxWidth / PhotoMaxHeight720 / 405Size of a captured photo. Smaller means less to store and less to load when the phone opens.
Config.PhotoLimit30Photos kept per phone. Taking one more deletes the oldest.
Config.PhotoMaxLength1500000Largest single photo (characters of base64). Bigger ones are refused.
Config.VoiceMaxSeconds20Longest voice note. The recorder stops on its own at the limit.
Config.MediaMaxLength400000Largest attachment kept on a message. Anything bigger is dropped and the message sends without it.

Media storage

Photos and voice notes start life as images and audio inside the phone. Config.MediaStorage decides where they end up:

  • 'database' (default): stored directly in MySQL. Nothing to set up. The cost is database size and how much each phone loads on open, which the photo limits above keep in check.
  • 'remote': uploaded to a file host, and only the link is stored. Better for big servers.

Setting up remote uploads

Open server/upload.lua (server-only, so the key stays private). The defaults are set up for Fivemanage, so you only need to paste your key:

local Upload = {
    url = 'https://api.fivemanage.com/api/v3/file',               -- multipart uploads
    base64Url = 'https://api.fivemanage.com/api/v3/file/base64',  -- JSON uploads
    token = 'YOUR-API-KEY',
    header = 'Authorization',   -- or 'x-api-key', ...
    tokenPrefix = '',           -- or 'Bearer ', ...
    field = 'file',             -- multipart field name
    timeout = 15000,
}

Then set Config.MediaStorage = 'remote' in config.lua.

  • Most hosts work, not just Fivemanage. The reply is searched for the usual link fields (url, link, data.url, …) or a bare URL.
  • If the host is down or rejects the upload, the photo or clip is stored in the database instead, so nothing is lost. The console prints the host's reply so you can see why.
