For developers

Make your own app

Any resource can put an app on the phone, with no changes to Royal Phone and no React. Your app is an HTML page in your own resource. The phone gives it an icon, opens it full screen and lets it talk to your Lua.

How it fits together

page  ──RoyalPhone.fetch('x')──▶  client.lua   RegisterNUICallback('x')
                                       │  lib.callback / TriggerServerEvent
                                       ▼
                                    server.lua  ──exports['royal-phone']:…──▶  phone
                                       │
page  ◀──RoyalPhone.on('y')───────  SendAppMessage(source, 'my-app', 'y', data)
  • The page is plain HTML, CSS and JavaScript (or any framework you build into it).
  • royal-phone.js is a small SDK the page includes. It talks to the phone and to your own client script.
  • royal-phone.css is an optional UI kit that makes your app look like the built-in ones.
  • Your Lua uses the phone's exports for anything phone-related: contacts, texts, notifications, storage.

Quick start: the template

The repository includes a complete, working example app in template/royal-phone-app. It shows the player's number, lists their contacts from the server, sends notifications and texts, receives pushes from the server, saves data, and opens Messages. Start from it.

  1. Copy it out

    Copy template/royal-phone-app into your server's resources folder, outside the royal-phone folder, and rename it, e.g. taxi-app.

  2. Start it after the phone 
    ensure royal-phone
ensure taxi-app
  3. Rename the app

    Change APP_ID at the top of client.lua and server.lua, and the name and icon in client.lua.

  4. Build your screen

    Replace ui/index.html and ui/app.js with your app. Keep royal-phone.js and royal-phone.css.

Step 1: register the app

From your client script:

local function register()
    exports['royal-phone']:CustomApp({
        id = 'taxi',                -- unique; letters, numbers, - _ .
        name = 'Taxi',              -- label under the icon
        icon = 'ui/icon.png',       -- a file in your resource, or a full URL
        ui = 'ui/index.html',       -- a file in your resource, or a full URL
        background = '#0b0c10',     -- shown behind the page while it loads
    })
end

-- The phone fires this when it starts, and whenever another resource starts.
AddEventHandler('royal-phone:client:registerApps', register)

-- Covers your resource restarting while the phone keeps running.
CreateThread(function()
    if GetResourceState('royal-phone') == 'started' then register() end
end)
  • Paths are relative to your resource. 'ui/index.html' becomes https://cfx-nui-taxi/ui/index.html automatically.
  • List the files in your fxmanifest.lua, or FiveM won't serve them:
files {
    'ui/*',
    'ui/**/*',
}
  • Your app is removed automatically when your resource stops, and comes back when it, or the phone, restarts.
  • Players can move your icon like any other app. New apps are added to the home screen on their next open.

Step 2: build the page

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8" />
    <link rel="stylesheet" href="royal-phone.css" />
</head>
<body>
    <div class="rp-app">
        <header class="rp-header">
            <div class="rp-header-text">
                <h1 class="rp-title">Taxi</h1>
                <p class="rp-subtitle" id="who"></p>
            </div>
        </header>

        <main class="rp-scroll">
            <button class="rp-btn rp-btn-primary rp-btn-block" id="book">Book a ride</button>
        </main>
    </div>

    <script src="royal-phone.js"></script>
    <script src="app.js"></script>
</body>
</html>
RoyalPhone.ready().then((phone) => {
    // phone.number, phone.name, phone.job, phone.route, phone.settings
    document.getElementById('who').textContent = `Signed in as ${phone.name}`;
});

document.getElementById('book').addEventListener('click', async () => {
    const ride = await RoyalPhone.fetch('bookRide', { from: 'Legion Square' });
    RoyalPhone.notify({ title: 'Taxi', content: `Driver on the way: ${ride.driver}` });
});
Build it in your browser

Open ui/index.html straight in a browser, or serve the folder with any static server. Outside the game, RoyalPhone.ready() resolves with a placeholder player and RoyalPhone.fetch(name, data, mock) returns mock, so the page works without starting FiveM. Pass realistic mock values and you can design the whole app this way.

Step 3: talk to your Lua

Every RoyalPhone.fetch('name', data) call arrives at a RegisterNUICallback('name') in your client script. From there, go to the server as you normally would:

RegisterNUICallback('bookRide', function(data, cb)
    cb(lib.callback.await('taxi:bookRide', false, data.from))
end)
local phone = exports['royal-phone']

lib.callback.register('taxi:bookRide', function(source, from)
    if type(from) ~= 'string' then return nil end   -- always validate: this came from a client

    local driver = 'Ray'   -- your dispatch logic here

    -- Text the customer from "Downtown Cab Co."
    phone:SendMessage(source, 'Downtown Cab Co.', ('%s is on the way to %s.'):format(driver, from))

    return { driver = driver }
end)

Pushing to the page

The server (or client) can send a message into your page at any time. The page listens with RoyalPhone.on:

phone:SendAppMessage(source, 'taxi', 'driverArrived', { plate = 'ROYAL 01' })
RoyalPhone.on('driverArrived', (data) => {
    showBanner(`Your taxi (${data.plate}) is outside`);
});

Saving data

Use the phone's per-app storage instead of creating your own table. It's stored per phone, so with SIM cards on, the data follows the SIM:

phone:SetAppData(source, 'taxi', 'favourites', { 'Legion Square', 'Pillbox' })
local favourites = phone:GetAppData(source, 'taxi', 'favourites') or {}
phone:SetAppData(source, 'taxi', 'favourites', nil)   -- delete

Values can be anything json.encode accepts, up to 64 KB per key.

Notifications & deep links

Notifications from your app show your icon. Give one a route and tapping it opens your app with that data, so you can jump to the right screen:

phone:Notify(source, {
    app = 'taxi',
    title = 'Ride complete',
    content = 'Tap to rate your driver',
    route = { screen = 'rate', ride = 42 },
})
// Opened from the notification:
RoyalPhone.ready().then((phone) => { if (phone.route) openScreen(phone.route); });

// Already open when the notification was tapped:
RoyalPhone.on('route', (route) => openScreen(route));

You can also open your app from Lua, for example from a command or an item:

exports['royal-phone']:OpenCustomApp('taxi', { screen = 'book' })

Back & Escape

By default, Esc inside your app goes back to the home screen. If your app has sub-screens, handle it yourself and only leave when you're on the first screen:

RoyalPhone.on('back', () => {
    if (currentScreen !== 'home') showScreen('home');
    else RoyalPhone.back();
});

SDK reference

CallWhat it does
RoyalPhone.ready()Promise that resolves once the phone has introduced itself, with { appId, resource, number, name, job, route, settings }. In a browser it resolves with placeholder data.
RoyalPhone.fetch(name, data, mock?)POST to RegisterNUICallback(name) in your own client script and return its answer. Returns mock outside the game.
RoyalPhone.on(type, fn)Listen for SendAppMessage pushes, 'route' (opened again from a notification) and 'back' (Escape). Returns an unsubscribe function.
RoyalPhone.notify({ title, content?, duration?, sound?, route? })A phone notification with your app's icon.
RoyalPhone.openApp(id, route?)Open another app, e.g. openApp('messages', { number: '555-0134' }) or openApp('dialer', { tab: 'keypad' }).
RoyalPhone.back()Same as the phone's back gesture.
RoyalPhone.close()Back to the home screen.
RoyalPhone.inGametrue inside FiveM, false in a browser.
RoyalPhone.stateThe same object ready() resolves with, kept up to date.

The SDK also handles two things an embedded page can't do on its own:

  • Typing: it tells the phone when one of your inputs has focus, so keys type instead of moving the character.
  • Safe areas: it sets --rp-top and --rp-bottom to the height of the phone's status bar and home indicator. .rp-app uses them so nothing hides behind the clock.

UI kit

royal-phone.css matches the built-in apps: same font, spacing, colours and components. Every class starts with rp-, so it won't clash with yours.

ClassUse it for
rp-appThe root of every screen. Full height, padded for the status bar and home indicator.
rp-header, rp-header-text, rp-title, rp-subtitleThe page header with its big title.
rp-icon-btnRound icon button for the header (back, close, add).
rp-scrollThe scrolling body under the header.
rp-sectionSmall uppercase label above a group.
rp-card, rp-flushA rounded surface. rp-flush for lists inside a card.
rp-list, rp-item, rp-avatar, rp-item-text, rp-item-title, rp-item-sub, rp-item-endContact-style rows with an avatar, two lines of text and something on the right.

rp-toggleA switch: <label class="rp-toggle"><input type="checkbox"><span></span></label>

Colours are CSS variables on :root (--rp-accent, --rp-bg, --rp-surface-card, …), so you can retheme the kit without touching it.

Using React, Vue or Svelte

Fine. Build your app into your resource (e.g. ui/dist), point ui at its index.html, and include royal-phone.js for the phone connection. Set Vite's base: './' so asset paths work under cfx-nui-.

Security

Treat everything from the page as untrusted

Your page runs on the player's machine, so anything it sends to your server can be faked. Check types and permissions on the server, and work out who is asking from source, never from the data you're sent.

Only install custom apps you trust: a page runs with the same NUI access as any other resource's interface.
