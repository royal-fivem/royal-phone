Reference

Database

You never run SQL by hand. On every start, the phone creates whatever tables and columns are missing.

Automatic setup

server/migrate.lua reads sql/royal-phone.sql on every start:

  • Every table is CREATE TABLE IF NOT EXISTS, so existing data is never touched.
  • New columns from updates are added with a checked helper (it looks in information_schema first), which works on every MySQL and MariaDB version.
  • New tables are printed to the console the first time they appear.

Updating the phone is just replacing the folder and restarting.

Who owns a row

Most tables have an identifier column. It holds the phone's owner:

  • with SIM cards on, the SIM serial (SIM-4821-0093);
  • with them off, the character identifier (citizenid, ESX identifier, …).

The exceptions are the bank tables (transactions, pending transfers, invoices and accounts), which always use the character, because money and debts don't move with a stolen SIM.

Phone & identity

TableHolds
royal_phone_numbersOwner → phone number. Numbers are unique.

royal_phone_settingsHome screen layout, wallpaper and settings per phone.
royal_phone_notesNotes per phone.

Calls, messages & contacts

TableHolds
royal_phone_contactsContacts per phone, with optional picture.
royal_phone_messagesEvery text: sender, receiver, content, attachments (image, voice, location) and read state.
royal_phone_groupsGroup chats: name, picture and owner.

Maintenance tips

  • Back up these tables with the rest of your database. Messages and photos are the biggest.
  • Photos make the database grow fastest with Config.MediaStorage = 'database'. Config.PhotoLimit caps them per phone. For big servers, switch to remote storage.
  • Wiping a player's phone: delete their rows by identifier (their owner key) in the tables above. Don't drop the tables while the server runs.
