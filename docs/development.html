For developers

Working on the UI

The phone's interface is React, Tailwind and framer-motion, built with Vite. This page is for changing the phone itself. To add an app from another resource, you don't need any of this: see Make your own app.

Dev server

You need Node.js 18 or newer.

npm --prefix web install
npm --prefix web run dev

Open http://localhost:5174. Outside FiveM the UI runs on mock data and shows a dev panel with buttons for notifications, incoming texts, a text storm, an incoming call, opening and closing the phone and resetting the layout. Most work can be done here without starting the game.

Against a live server

To see changes in game with hot reload, point ui_page at the dev server in fxmanifest.lua and restart the resource:

-- ui_page 'web/build/index.html'
ui_page 'http://localhost:5174/' -- dev
Switch it back before you ship

With the dev line active, only the machine running npm run dev sees the phone. Everyone else gets a blank screen.

Building

npm --prefix web run build

This writes web/build/. The build is committed on purpose: it's what makes the resource drop-in for servers that never touch the UI. Rebuild and commit it whenever you change anything in web/src.

How it's put together

PartResponsible for
client/main.luaOpening, closing, focus, keybinds, the animation, and every message to the UI.
client/apps/*.luaClient logic per app: calls and voice, camera, messages, custom apps.
server/*.luaAll database access and anything a client mustn't be trusted with. identity.lua answers "whose phone is this?", api.lua holds the public exports.
bridge/The framework adapters. The only files that know what QBX or ESX is.
web/srcThe interface. NuiBridge.jsx is the only place that listens to Lua.

What happens when the phone opens

  1. The key or /phone calls Toggle() in client/main.lua.
  2. It checks the item, the SIM, and whether the player is dead or cuffed.
  3. It fetches everything in three callbacks (getData, li:getData, docs:getData) and sends one bootstrap message to the UI.
  4. NuiBridge hands each part to its store, and the UI renders.

There's no polling. When something changes server-side (a new message, a call, a shared document), the server pushes it to the clients that need it. For bigger changes it sends a refresh for one slice, which the client re-reads only if the phone is open.

Talking between Lua and the UI

Lua → UI: PhoneSend(action, data) in Lua, useNuiEvent(action, handler) in NuiBridge.jsx.

PhoneSend('notify', { app = 'bank', title = 'Deposit', content = '$2,500 received' })
useNuiEvent('notify', (data) => notify(data || {}));

UI → Lua: fetchNui(name, data, mock) in the UI, RegisterNUICallback(name) in Lua. The third argument is what the call returns in a browser, which is what makes the UI runnable outside the game.

const result = await fetchNui('docs:save', { id, title, body }, { id: 1 });
RegisterNUICallback('docs:save', function(data, cb)
    cb(lib.callback.await('royal-phone:server:docs:save', false, data) or false)
end)

Adding a built-in app

  1. Write the screen

    Create web/src/apps/MyApp.jsx. It receives app (its config entry) and initial (the notification route it was opened with, if any).

  2. Register it

    Import it in web/src/config/apps.jsx and add an entry to APPS:

    {
    id: 'taxi',                 // stored in players' layouts: never rename a live id
    label: 'Taxi',
    icon: Car03Icon,            // Hugeicons glyph, used when there's no artwork
    gradient: 'bg-gradient-to-br from-amber-300 to-amber-600',
    background: 'bg-[#0b0c10]', // the app's backdrop
    component: TaxiApp,
}
  3. Add server data if you need it

    Add a table to sql/royal-phone.sql (always CREATE TABLE IF NOT EXISTS), a server file in server/apps/ with lib.callback.register handlers, and a client file in client/apps/ with matching RegisterNUICallbacks. Both folders are loaded automatically.

  4. Rebuild

    npm --prefix web run build. The app appears on everyone's home screen.

Design language

The Phone app (DialerApp.jsx) is the reference. Copy these and your app will look like it belongs:

ElementClasses

Scroll bodyroyal-scroll min-h-0 flex-1 overflow-y-auto px-5
Section labeltext-[11px] font-semibold uppercase tracking-[0.16em] text-white/35
Cardrounded-2xl bg-white/[0.06], no border
List rowflex items-center gap-3 py-2.5 with a 44 px round avatar
Inputrounded-2xl bg-white/[0.07] px-4 py-3
Bottom navmx-4 mb-1 flex shrink-0 items-center justify-around rounded-3xl bg-white/[0.05] p-1.5
  • Sky blue is the accent: badges, active states, primary buttons.
  • Emerald means money or "live". Rose is only for destructive actions.
  • Surfaces are white at low opacity over the app's own background: 0.05 nav, 0.06 cards, 0.07 inputs.
  • Apps are full-bleed: the status bar and home indicator sit on top of the app's own colour.

Sizing

Nothing uses fixed pixel sizes for the phone itself. web/src/utils/usePhoneMetrics.js measures the screen and publishes CSS variables, all fractions of the phone width (--pw): --status-h (status bar height), --chrome-b (home indicator height), --icon, --pad and so on. App screens are wrapped in ScreenScale, which uses CSS zoom so a 15 px label stays 15 px relative to the phone at every size.

Gotchas

No framer-motion layout or drag inside an app screen

ScreenScale applies CSS zoom. framer-motion measures in zoomed pixels but animates in unzoomed ones, so the element jumps or flies off by exactly the zoom factor. Animate x, y, opacity or height explicitly instead, or move the element outside the zoom box and size it off --pw, as the notification stack does.

  • Never build objects in a store selector. useStore((s) => s.list.filter(...)) returns a new array every time and React re-renders forever. Select the raw fields and derive with useMemo.
  • Tailwind translate + framer animate on one element doesn't work: framer's inline transform wipes Tailwind's. Wrap it in a static centring element.
  • New icons and sounds need a dev server restart. They're collected at build time with import.meta.glob, which Vite caches.
  • Press Enter explicitly. Implicit form submission is unreliable in NUI. Handle onKeyDown for Enter, like the message composer does.
  • Treat player content as untrusted. Documents run through the allow-list in utils/richtext.js on the way in and out. Extend the list rather than bypassing it.

Stores

State lives in Zustand stores in web/src/state/:

StoreHolds
phoneStoreOpen state, layout, dock, active app, settings and the current call.
dataStoreNumber, name, contacts, messages, groups, calls, photos and bank figures.
notifyStoreVisible toasts, notification history and unread bubbles.
lifeinvaderStoreAccounts, posts, listings, follows.
documentsStoreDocuments, debounced saving, invites and signatures.
cameraStoreCamera mode, zoom and capture state.
customStoreApps registered by other resources.

Icons, sounds & wallpaper

App icons

Drop a <app-id>.webp into web/src/assets/icons/ (Bank.webp, Garage.webp…) and it replaces that app's gradient tile everywhere: home screen, dock, notifications. Names match case-insensitively, and an app entry can point at a different file with image (that's how dialer uses Phonecall.webp). Rebuild afterwards.

Sounds

File in web/src/sounds/Plays when
newnotification.mp3A notification arrives.
newmessagesent_inapp.mp3You send a message.
ringtone.mp3A call rings in. Loops until it's answered, declined or ends.

Replace a file with your own (same name) and rebuild. Players control volume and mute in Settings.
