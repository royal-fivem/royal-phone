Getting started

Installation

About five minutes. You don't import any SQL or run a build. The interface is pre-built and the database sets itself up.

Before you start

Make sure these are installed and started on your server:

  • ox_lib and oxmysql: both required.
  • Your framework (QBX, ESX, ox_core or ND), unless you run standalone.
  • Optional: pma-voice for call audio, screencapture for the camera, and ox_inventory for the phone item and SIM cards.

Install

  1. Download and place the folder

    Download the latest release (or clone the repository) and put the royal-phone folder in your resources, for example resources/[phone]/royal-phone. Keep the folder name royal-phone: other resources call its exports by that name.

  2. Start it after its dependencies

    In your server.cfg:

    ensure ox_lib
ensure oxmysql
# your framework, inventory and pma-voice here
ensure royal-phone
  3. Pick your framework

    Open config.lua and set Config.Framework to 'QBX', 'ESX', 'OX', 'ND' or 'STANDALONE'.

    Config.Framework = 'QBX'
  4. Add the items

    Copy the phone and simcard definitions from ox_inventory_items.lua into ox_inventory/data/items.lua. See the items below. If you don't want items at all, set Config.RequireItem = false and Config.RequireSim = false.

  5. Check the UI page

    Open fxmanifest.lua and make sure the build line is active and the dev line is not:

    ui_page 'web/build/index.html'
-- ui_page 'http://localhost:5174/' -- dev
    The phone is blank in game?

    If ui_page points at http://localhost:5174/, the phone loads from a development server that only exists on the developer's machine. Every other player sees nothing. Always ship with web/build/index.html.

  6. Start the server

    On first start the console prints a line for every table it creates, for example [royal-phone] created table royal_phone_messages. Press M in game, or type /phone, and the phone opens.

The items

ox_inventory_items.lua holds the exact definitions to paste. ox_inventory doesn't read that file itself; it only exists so you have something to copy.

['phone'] = {
    label = 'Phone',
    weight = 190,
    stack = false,
    description = 'Useless without a SIM card.',
    container = {               -- the SIM tray (needs an ox_inventory with item containers)
        label = 'Phone',
        slots = 1,
        maxWeight = 2000,
        whitelist = { 'simcard' },
    },
    buttons = {
        {
            label = 'Open SIM tray',
            action = function(slot)
                exports.ox_inventory:openInventory('container', slot)
            end,
        },
    },
},

['simcard'] = {
    label = 'SIM Card',
    weight = 10,
    stack = false,              -- never let SIM cards stack
    close = false,
    description = 'A blank card registers itself to the first phone it goes in.',
},
Item names must match config.lua

Config.ItemName (default 'phone') and Config.SimItem (default 'simcard') must be the names you used here. If they don't match, the phone says "You do not have a phone" or "No SIM card".

The container block turns the phone into a one-slot SIM tray. It needs an ox_inventory build with item containers. If yours doesn't have them, leave the block out: a SIM card loose in the player's pockets works too. See SIM cards.

Running without items

For an "everyone has a phone" server:

Config.RequireItem = false   -- no phone item needed
Config.RequireSim  = false   -- the number belongs to the character

Each character then gets a number automatically the first time they open the phone. On frameworks that already store a phone number (QBX's charinfo.phone, for example), that number is used.

Call audio (pma-voice)

With Config.Voice = 'pma-voice' (the default) and pma-voice running, both sides of a call are put on the same call channel when the call is answered. pma-voice isn't a hard dependency: without it, calls still ring, connect and show in the log, just without audio. Load order doesn't matter.

Camera (screencapture)

The Camera app needs screencapture to save photos. Without it the shutter reports a failure rather than saving a blank image. Photos are stored in the database by default. To keep them on an upload host instead, see media storage.

Updating

  1. Back up your config.lua and server/upload.lua (if you set an upload key).
  2. Replace the folder with the new version and put your two files back.
  3. Restart. New tables and columns are added automatically on start, so you never run SQL by hand.
Quick test

Type /testnotify for a notification, or /testmessage hello to text yourself. If both show up, everything is wired correctly.
