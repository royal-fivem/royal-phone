Troubleshooting & FAQ

Most problems come down to item names, start order or one line in fxmanifest.lua. Check the server console and the F8 console first: the phone prints a clear message for most failures.

Common problems

The phone opens, but it's blank or invisible

  • Open fxmanifest.lua. If ui_page 'http://localhost:5174/' is active, the phone is loading from a developer's machine. Switch to ui_page 'web/build/index.html' and restart.
  • Make sure web/build/ exists and contains index.html and an assets folder. If you downloaded the source without the build, run npm --prefix web install and npm --prefix web run build.

"You do not have a phone"

  • The item name in your inventory must match Config.ItemName (default 'phone').
  • Config.Inventory must match the inventory you actually run.
  • For a server where everyone has a phone, set Config.RequireItem = false.

"No SIM card. Put one in the phone."

  • The SIM item must exist in ox_inventory and match Config.SimItem (default 'simcard'). Older versions used 'sim_card'.
  • The card must be in the phone's SIM tray or in the player's pockets.
  • Don't want SIM cards? Set Config.RequireSim = false.

Pressing M does nothing

  • The player may be dead, cuffed or swimming. That's intended (see Config.BlockWhenDead and Config.BlockWhenCuffed).
  • The key may have been rebound. Check Settings › Key Bindings › FiveM, or try /phone.
  • The character may not be fully loaded yet in your framework.
  • Check that ox_lib and oxmysql start before royal-phone.

Calls connect but nobody can hear each other

  • Is pma-voice running? Calls connect without it, just silently.
  • Check Config.Voice = 'pma-voice'.
  • Make sure pma-voice's call channels aren't disabled in your pma-voice convars.

The camera says the photo failed

  • The Camera needs screencapture started on the server.
  • With remote storage, check the server console for the upload host's reply. A wrong key or endpoint is printed there. The photo is still saved to the database as a fallback.

Bank transfers fail

  • The sender needs enough money in their bank account.
  • The number must belong to someone who has opened a phone at least once.
  • The amount may be over Config.BankMaxTransfer. The error says the limit.
  • On standalone (or ox_core without accounts) the phone's own bank balance starts at 0, so there may simply be nothing to send yet.

Invoices don't arrive

  • Check Config.BankInvoices = true. With it off, AddInvoice returns false and the tab is hidden.
  • AddInvoice needs an online player source and a positive amount.

The Garage is empty

  • Standalone has no vehicles. On other frameworks the vehicles come from the framework's own table. If you use a custom garage resource with its own table, adjust Bridge.GetVehicles in your bridge file.

Notifications don't show while the phone is pocketed

  • Check Config.NotifyWhenClosed = true.
  • The player may have Do not disturb on (Settings › Notifications).

My custom app doesn't appear

  • Look in F8 for a CustomApp: warning: an invalid id, a missing ui, or an id another resource already uses.
  • Your ui/ files must be listed in your fxmanifest.lua files { }.
  • Start your resource after royal-phone, and register on the royal-phone:client:registerApps event. See Step 1.
  • If keys typed in your app move the character, your page isn't including royal-phone.js.

Database errors on start

  • Check oxmysql connects (its own console line on start).
  • The database user needs permission to CREATE and ALTER tables, since the phone sets up its own tables.

FAQ

Does it work with qb-core?

There's no qb-core bridge out of the box, but the QBX bridge is very close to what qb-core needs. Copy it and change the export calls. See Adding another framework.

Can a player have more than one number?

Yes, with SIM cards on. Each SIM card is its own number with its own contacts and messages. Swap cards to swap numbers.

Can I change a player's number?

Update the number in royal_phone_numbers (and royal_phone_sims with SIM cards on) while the player is offline. Existing messages and call logs keep the old number, so threads with other players will start fresh.

Why can't I click the phone when it peeks up in game?

On purpose: the peek never takes the mouse, so a notification can't interrupt driving or a firefight. Press M during the peek to open the phone straight on that notification.

Is it heavy on the server?

No. Nothing polls. Data is read once when the phone opens, changes are pushed only to the players they concern, and the per-frame code runs only while the phone is on screen.

Can I translate it?

Not through a config file yet. Texts are written in the UI source (web/src), so translating means editing those files and rebuilding.

Known limitations

  • Airplane mode and hide previews in Settings are saved, but don't change anything yet.
  • Calls ring until the caller hangs up. There's no automatic timeout yet.
  • Documents aren't edited live together. If two people edit the same document at the same time, the last save wins.
  • The peek can't be clicked in game (see above). Use M.

Still stuck?

Open an issue on GitHub with your framework, inventory, the relevant lines from the server and F8 consoles, and what you expected to happen.
